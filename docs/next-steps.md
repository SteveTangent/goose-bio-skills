# 下一步计划：用现有输入和流程断点驱动扩展

更新：2026-09-12。当前 60 个 Skill、42 个内置 helper；表达流程、单细胞小对象路径和分析交接已实现。当前拿不到用户反馈，因此本计划按**现有输入是否可接、能否补齐下游、能否跨任务复用、实施与解释代价**排序。它是工程优先级建议，不是已验证的市场需求。A1/A2 已实现；B1/B2 本批补齐为 0.14.0 reviewed preview，并接入原生交接、图表和报告。C 项尚未实施。

[领域能力画像](capability-profile.md) 显示：表达、单细胞小数据、富集和统计已有较完整的有限路径；微生物和蛋白组的小数据路径已连接计算、图表与报告。变异和化学信息执行较薄，但不为把雷达图填满就同时扩展所有领域。

**A/B 两批已实施；下一批推荐 C1：同版本 BED3 区间相交/合并**。优先增强既有 genomic-interval-operations，接到峰集 QC；不再增加一个重叠的入口 Skill。然后在 C2 中先选“小分子 SMILES 检查与描述符”作为化学信息的窄执行入口，结构方向待明确需求再做。两项分批，保留小输入与科学语义边界。

## 为什么与上一轮顺序有所调整

原先建议拿到反馈后优先 qPCR。现在无法获得反馈，仍可先从代码可见的断点做决策：蛋白组已有差异模型但 QC 仍无内置脚本；微生物已有距离计算但不能直接生成排序图。这两项对现有能力的复用更直接。qPCR 与独立 2×2 已在第二小批补齐；不因其能提升某个雷达分值而自动实施。

## 生物信息学上必须保留的边界

qPCR 不能不检查效率条件就一律套用 `2^-ΔΔCq`；重复单位、参考基因依据和效率处理要进入输入契约。统计建模在合适的量/变换尺度上完成，不能对技术重复直接增加样本数。方法设计参考 [MIQE 2.0 原始建议](https://www.gene-quantification.de/bustin-et-al-miqe-2.0-clinical-chemistry-2025.pdf) 与 [MIQE 官方入口](https://rdml.org/miqe.html)。

PCoA 是距离排序，PCA 是特征矩阵的主成分分析，不能改个图名互相替代。若以后增加 PERMANOVA，需要同时考虑组内离散程度与置换限制；显著结果不一定只反映组中心不同。这是把组间推断留到后续的原因，参见 [vegan 的方法说明](https://vegandevs.github.io/vegan/reference/adonis.html)。

2×2 表应明确独立性、行列方向和抽样设计，Fisher 检验返回的效应估计与置信区间方法要分别声明，参见 [SciPy 官方接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.fisher_exact.html)。这些在线说明只用于方案核对；实施时单独冻结实际依赖。来源核对日期：2026-09-12。

## 除了新增 Skill，流程还需什么

| 项目 | 最小维护方式 | 价值 |
| --- | --- | --- |
| 入口矩阵 | 维护“我有何种文件 → 我想回答什么 → 对应 Skill → 必须补哪条事实”表，放在现有 task bundles，不建第二套路由系统 | 无反馈时也能按常见文件检查是否存在断路 |
| 输入和失败示例 | 每个新/改适配器保留一个可运行正例及 2–3 个能发现实质错误的反例；优先不足 100 KB 的表，公开下载通常限制在 1 MB 内 | 比只检查目录格式更能发现问题，维护代价低 |
| 结果交接 | 只在确有上下游关系时扩展现有 companion 的原生结果支持；保持独立安装和单步可用 | 让蛋白/微生物结果复用图表报告，避免一个新框架 |
| 环境说明 | 给每个任务包列出所需 Python/R 版本、是否已有 doctor 覆盖，以及超限时的交接办法 | 减少“装上 Skill 却跑不起来” |
| 版本与能力图 | 盘点图绑定 registry 和 manifest；范围改变后人工复核档位；按实际成熟度另行准备集合预览版 | 避免 README、包数、可执行状态与发布标签不一致 |

主框架暂不重构：沿用“一项工作一个 Skill + 明确输入输出 + 可选原生结果交接 + 共用图表报告”。不增加中央调度服务、插件继承体系、数据库或遥测收集。共享科学 I/O 只有在实际重复修复造成负担时再评估抽取，不能破坏独立安装。

## 每一小批怎样收尾

1. 用输入和输出写清唯一工作，复用现有包边界；不要默认猜测物种、分组、尺度或独立性。
2. 一份小数据真正产生文件和图；用反例检查需要澄清/工具/不支持时的状态。
3. 核对跨步骤 ID、单位、方向、缺失处理、版本和文件指纹；保留明确的效果/距离/统计语义。
4. 做范围适配的代码审查和仓库检查，随后上传合并；更新领域画像依据，而非先设提分目标。

暂缓空间组学、细胞通讯、轨迹、多组学网络、大型原始数据处理和临床决策。这些不是库的禁区，而是当前“小而常用”定位下收益与依赖/解释负担不匹配的下一步。
