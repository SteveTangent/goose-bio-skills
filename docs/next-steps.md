# 下一步建议：补齐工作流程，再扩展少量常用分析

状态：建议，尚未实施或纳入 registry。依据是当前 56 个 Skill、37 个 helper 和六个安装任务包的实际边界；不是使用频率调查或效果排名。

## 先做的流程改进

| 优先级 | 增加什么 | 最小实现 | 完成标准 |
| --- | --- | --- | --- |
| P1 | 按输入和问题找入口 | 扩充现有任务包页面：我有什么文件、想回答什么、下一步用哪个 Skill、还缺哪个关键事实 | 三条已有流程能从中途接入；不需要用户理解 Domain/Cluster |
| P1 | 可复用的分析简报 | 一个小型项目文件，记录物种、实验类型、数据尺度、独立样本单位、分组与比较方向；区分用户确认、文件证据和未知项 | 已确认事实在下一步直接复用；输入变化后重新检查；不自动填充生物学事实 |
| P1 | 结果交接与恢复 | 在现有原生输出之外记录输入校验值、Skill/工具版本、参数、产物路径和状态；先用于三条现有流程 | 从失败步骤恢复；输入或参数改变时使旧结果失效；不把 partial/needs-decision 交给下游当成功 |
| P2 | 一份面向用户的结果入口 | 复用现有报告和 methods.md，增加结果目录、图表用途、未解决问题和下一步 | 用户打开一份文件即可找到图、表、方法和需要补充的事实 |
| P2 | 安装及依赖的清晰边界 | 在现有 doctor 上逐步覆盖剩余 helper，按任务包说明 Python/R 环境和版本 | 无依赖的环境准确指出缺项；未检查保持显式；不自动修改全局环境 |
| P2 | 明确的版本交付入口 | 维护当前 main 预览说明；另行准备有版本、校验值、安装说明和回滚对象的集合预览发布 | 不再混淆不可变 v0.9.0 集合、当前 main 和单包版本；合并本身不创建发布标签 |

建议先把“简报 → 当前 Skill → 交接清单 → 已有报告”跑通。继续保持独立可安装包和离线 helper；暂不引入中央调度服务、数据库、插件继承层或统一科学计算 API。交接清单只描述文件与状态，保留不同分析各自的科学字段。先在现有流程中获得复用价值，再判断是否值得抽象。

## 推荐的下一批分析

| 顺序 | Skill | 当前缺口与价值 | 第一版边界 |
| --- | --- | --- | --- |
| 1 | 标准化表达矩阵差异分析 | 公共表达矩阵已能整理，但处理过的微阵列表达值不能直接送入 raw-count DESeq2；现有蛋白 limma helper 也限定蛋白输入 | 一个平台、明确为已归一化 log2 的微阵列表达、两个独立组、至多一个分类调整变量；输出效应/FDR/QC，复用现有图表和报告 |
| 2 | qPCR 相对表达与 QC | 补上常见实验室验证数据的整理、技术重复汇总和出图劳动 | 一种已声明的 ΔΔCq 方法；明确对照、参考基因、扩增效率适用条件及重复单位；保留 undetermined 和 QC 异常，不把技术重复当独立样本 |
| 3 | 两组分类结局比较 | 当前新增两组分析面向连续测量，阳性率/比例的 2×2 数据仍缺专用执行路径 | 独立样本的一个 2×2 非负整数计数表；预先声明方向和检验，给出分母、效应及区间；正确报告零单元格和不可估计值，排除配对及复杂回归 |

这些方法需要的边界可从 [limma 官方指南](https://bioconductor.org/packages/release/bioc/vignettes/limma/inst/doc/usersguide.pdf)、[MIQE 对 qPCR 的设计、参考基因和效率要求](https://rdml.org/miqe.html)、[SciPy Fisher 精确检验接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.fisher_exact.html)核对。来源核查日期：2026-09-10。排序是结合当前仓库缺口的工程建议；实施时另行冻结依赖版本，不因在线文档更新自动升级运行环境。

每项沿用轻量标准：一个微型正例、能发现实质错误的输入反例、一次图表/报告交接、代码审查和依赖说明。保持 `preview + reviewed`，不要求正式 Agent 对照实验。暂缓轨迹推断、细胞通讯、复杂多组学整合和自动最终细胞注释；这些会显著扩大依赖及解释负担。
