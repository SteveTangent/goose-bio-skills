# 从表达数据到可解释结果

先按输入选择方法：

| 我有什么 | 当前入口 | 必须确认 |
| --- | --- | --- |
| 一个 GEO Series Matrix | 公共表达准备；确认后接微阵列或其他适用方法 | 平台、数值尺度、样本与处理方法 |
| 已归一化的 log2 微阵列矩阵 | 样本检查 → 微阵列差异 → 映射 → 富集 → 图表报告 | 探针/基因单位、独立对象、比较方向、归一化证据 |
| 原始基因 counts | 样本检查 → DESeq2 → 映射 → 富集 → 图表报告 | 原始计数来源、独立对象、分类调整变量 |
| 已检查的 pseudobulk counts | 从 counts 接入同一条流程 | 细胞类型已审核；按供体/样本汇总的是原始 counts；保留排除与样本事实 |
| 只有 TPM/FPKM 或尺度未知 | 保留为待补充，核对生成步骤 | 不通过取整或改名假装原始计数，也不自动当作微阵列 |

使用 [微阵列模板](../examples/workflow/microarray-expression.json) 或 [计数模板](../examples/workflow/rnaseq-expression.json)。模板没有执行命令，参数是合成示例占位值。Agent 根据实际文件填写并确认事实；用户不必维护 JSON。沿用 [已有流程工具](analysis-workflow.md) 的 status、confirm、record 和 overview。即使已经有结果，中途接入仍需核对原生版本、输入与产物。

## 样本与参考资源

维护一张原始样本表，包括 sample_id、condition、subject_id 和实际存在的 batch。样本检查可以输出适配后的模型与绘图样本表，同时保留完整原表。重复 subject_id 需要澄清是技术重复还是配对；当前表达模型只支持独立组。完全混杂的分组与批次不能靠添加 batch 解决。

参考资源先选择物种、平台和版本，再导出需要的映射列或 GMT。已有 ID Skill 的 reference preparation 模式转换到 mapping.tsv/gene-sets.tsv，记录来源文件指纹、重复记录与资源声明。暂不自动下载注释数据库。探针一对多、多探针对同一基因仍显式保留；不得按观察到的显著性挑一个探针。

## 先看 QC，再解释差异

检查样本数与独立对象数，查看同一 PCA 按分组、按批次着色的图，再看样本相关性。图形异常需要原始 QC 或实验记录支持，不自动删除样本。原始 counts 的现有绘图路径使用 DESeq2 size factors 后的 log2(count+1)，属于探索性诊断；需要 VST/rlog 等处理时采用明确的上游转换。

微阵列模型保留 probe/gene 单位，给出 log2 效应、点置信区间和 BH 校正结果。映射后选定 ORA 的合格背景或完整有符号排名。GSEA 必须使用交接记录中的 ranking_metric 与 positive_direction：微阵列为 moderated t，DESeq2 为 Wald statistic。没有选中基因时可以省略 ORA 并如实报告；不要为了得到富集结果反复调整阈值。富集及排序的方向不单独证明通路激活。

## 环境与大小

现有两个 R 路径分开使用：微阵列检查 R 4.4.1 / limma 3.60.6；DESeq2 按其适配器声明实际版本。运行前对所选任务包执行 doctor，确保它看到的是当前任务环境中的 Rscript。不同 R 版本无需覆盖安装到一起。脚本不自动安装环境。

本次原生结果交接支持最多 16 MiB 的结果 JSON；计划与回执仍限制为 1 MiB。微阵列输入及结果 JSON 各不超过 8 MiB，最多 32 个样本；这是明确的执行边界，不代表任意真实数据均可运行。单细胞 8 MiB/矩阵规模限制继续保留，未在本次扩容。超限时保留完整原始对象，在可信本地环境完成适用的上游处理，交接符合本库契约的小表或结果；不要任意删细胞、删基因来通过限制。

对模型范围外的数据，用清楚的外部分析说明接入现有通用表格作图/报告路径；任意外部 JSON 不能冒充原生分析回执。
